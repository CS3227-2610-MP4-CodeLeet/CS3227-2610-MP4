## Follow-up interaction: Preview runner unavailable

The user reported that the Vercel PR Preview still showed `Runner unavailable` and asked why Pyodide and TeaVM should not simply be installed as dependencies. A temporary local route exercised the same-project `srcdoc` path under `VERCEL_ENV=preview`, with Chromium console/frame diagnostics. This reproduced the failure: the nested supervisor's inline script used a different CSP nonce, and Pyodide WebAssembly instantiation was blocked by the inherited outer sandbox CSP. After passing the parent nonce to the nested supervisor, a Java smoke exposed a further TeaVM `EvalError` because the inherited sandbox CSP rejected JavaScript string evaluation.

Scoped the CSP repair to the opaque runner iframe: it now receives the outer per-run nonce and allows `'unsafe-eval'` inside that sandbox only. `connect-src 'none'`, `default-src 'none'`, `sandbox="allow-scripts"` without `allow-same-origin`, and the authenticated app CSP remain unchanged. A focused bridge unit test checks the CSP and nonce handoff. Local same-project Playwright smoke passed Python and Java separately in Chromium (both reported Completed with expected output); the temporary route/config/spec were removed. The failed Java run before the final CSP change produced the expected `EvalError`, establishing the regression cause.

This explains why adding package dependencies alone would not cure the Preview failure: package installation supplies files for the build, while the browser still enforces the sandbox's ancestor CSP. Pyodide documents that its npm package comprises a runtime file distribution that must be served; TeaVM-javac documents direct loading of its WASM module, runtime loader and class library files. Package-managed assets could simplify pinning/copying, but do not configure the deployment CSP or replace the app's same-origin static asset path. References: https://pyodide.org/en/stable/usage/downloading-and-deploying.html and https://github.com/konsoletyper/teavm-javac.
