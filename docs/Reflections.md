| Question | What happened | What we learned |
| --- | --- | --- |
| When did specialists help? | Runtime research, threat review and independent browser tests found different defects; the Java input follow-up used one implementation owner and reused the harness. | Delegate distinct, high-risk questions; keep tightly coupled repair with one owner. |
| What context was useful? | Current contracts and executable acceptance cases exposed outdated preview guidance in historical material. Synthetic packet comparisons quantified constructed input size. | Start with the active contract and retrieve history only when it resolves a specific uncertainty. |
| What made a claim credible? | A failed dashboard recovery test followed the reviewer finding, and a repaired runtime boundary passed independent replay. | Turn an agent's finding into a reproducible test and check the user's outcome. |
