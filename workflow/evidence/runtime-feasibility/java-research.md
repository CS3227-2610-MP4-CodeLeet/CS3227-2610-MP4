## Primary-source findings

### TeaVM-javac

**Documented fact:** The project's [README](https://github.com/konsoletyper/teavm-javac) describes OpenJDK javac and TeaVM compiled into a browser WebAssembly compiler. Its API accepts source files, emits diagnostics, compiles classes and generates executable Wasm. It provides a compiler worker protocol. Project licensing is Apache-2.0, with OpenJDK compiler components under GPLv2 plus Classpath Exception. This is source compilation, not merely loading an existing classfile.

**Actionable assets:** The documented public playground prefix is `https://teavm.org/playground/`. Required names are `compiler.wasm`, `compiler.wasm-runtime.js`, `compile-classlib-teavm.bin` (javac signatures) and `runtime-classlib-teavm.bin` (TeaVM implementation). These URLs are mutable; they are not immutable distribution pins. The README example accidentally supplies the compile-classlib URL twice; use the runtime-classlib URL described by the API for `setTeaVMClasslib`.

**Suggested API sequence, not an executed demo:** Import `load` from the companion runtime; load compiler bytes; call `exports.createCompiler()`; pass both classlib buffers through `setSdk` and `setTeaVMClasslib`; register diagnostics; add `Main.java`; require `compile()` success; require `generateWebAssembly({outputName: 'app', mainClass: 'Main'})` success; read `app.wasm`; instantiate those bytes with the same runtime; invoke the resulting `exports.main([])`. The four named assets and the application glue suffice for a minimal experiment with debug support disabled; additional dependencies must be discovered by inspecting actual downloaded loader bytes and network traces.

**Exact source version evidence:** [libs.versions.toml](https://raw.githubusercontent.com/konsoletyper/teavm-javac/master/gradle/libs.versions.toml) references TeaVM **0.13.1**, ASM **9.8**, jzlib **1.1.3**. [gradle.properties](https://raw.githubusercontent.com/konsoletyper/teavm-javac/master/gradle.properties) pins OpenJDK revision **6c48f4ed707bf0b15f9b6098de30db8aae6fa40f**. These are source dependency pins, not proof of playground binary provenance. A full immutable teavm-javac HEAD SHA could not be obtained in this session; never invent one. Source rebuilding should pin its full commit and resolved build dependencies, and archive hashes/license notices for all four produced assets.

**Fact:** [compiler/build.gradle](https://raw.githubusercontent.com/konsoletyper/teavm-javac/master/compiler/build.gradle) selects the **Wasm GC** backend and modular runtime and packages both classlibs into its distribution. Java 21 is a source-build prerequisite per README, not a claim that every Java 21 library works in resulting programs. [TeaVM classlib documentation](https://teavm.org/docs/runtime/java-classes.html) explicitly describes a partial library with semantic differences. [TeaVM overview](https://teavm.org/docs/intro/overview.html) identifies reflection, resource, classloader and JNI restrictions. Limit supported assignments to verified constructs.

**Stdout/stderr:** The upstream [frame.js](https://raw.githubusercontent.com/konsoletyper/teavm-javac/master/ui/src/main/webapp/frame.js) replaces `teavmConsole.putcharStdout` and `putcharStderr` through `installImports`, then calls `exports.main`. Its sample buffers until newline, uses wildcard message targets and lacks bridge validation/output bounds: do not copy that security posture. [worker.js](https://raw.githubusercontent.com/konsoletyper/teavm-javac/master/ui/src/main/webapp/worker.js) loads the compiler then invokes `exports.installWorker()`.

**Buffered stdin blocker:** In immutable-tag [TeaVM 0.13.1 TConsoleInputStream](https://raw.githubusercontent.com/konsoletyper/teavm/0.13.1/classlib/src/main/java/org/teavm/classlib/java/lang/TConsoleInputStream.java), both read overloads throw EOFException. [TSystem 0.13.1](https://raw.githubusercontent.com/konsoletyper/teavm/0.13.1/classlib/src/main/java/org/teavm/classlib/java/lang/TSystem.java) initializes System.in from that stream and exposes no setIn implementation. No loader stdin callback was established. **Inference:** Buffered stdin likely requires an explicit compiler/classlib adaptation and regeneration, rather than a JavaScript option. That adaptation must preserve submitted source and be separately reviewed/tested. Do not call this a complete solution for the existing stdin requirement.

**Current loader documentation, potentially newer than playground:** [Loader API](https://teavm.org/docs/wasm-gc-backend/loader.html) supports a byte buffer source and workers. Console hooks receive UTF-16 code units. Default automatic module importing can be disabled with `noAutoImports: true`; inspect the actual loader before relying on it. Its memory maximum addresses linear memory, while GC objects also occupy browser-managed memory. Debug deobfuscation fetches additional Wasm/debug assets. Shared memory requires COOP/COEP; ordinary nonshared worker execution does not imply SharedArrayBuffer is required. Exact supported browser minimum versions were not established; test Wasm GC support in each target browser.

**Isolation inference:** Run compilation and program execution in disposable workers under the separately reviewed credential-free origin/CSP boundary. Preload reviewed runtime bytes before running source, prohibit arbitrary imports/network capabilities, and terminate workers from the controlling context on deadline/output overflow. Worker termination and memory limits remain untested here. Wasm GC memory cannot be advertised as a strict per-program total memory cap.

### CheerpJ

**Fact:** The [4.3 documentation overview](https://cheerpj.com/docs/overview.html) describes a browser JVM/OpenJDK runtime supporting Java 8/11/17 and Java/JavaScript interoperability. This description alone is not evidence that javac ships in the default runtime. The vendor [architecture article](https://labs.leaningtech.com/blog/cheerpj-3-deep-dive) explicitly identifies running javac in CheerpJ as the JavaFiddle approach.

**Concrete compiler implementation:** Vendor [CheerpJ.svelte](https://raw.githubusercontent.com/leaningtech/javafiddle/main/src/lib/CheerpJ.svelte) places UTF-8 source at `/str/Main.java`, then runs `com.sun.tools.javac.Main` with `/app/tools.jar:/files/`, source path, `-d /files/` and `-Xlint`; only a zero compiler exit proceeds to running Main with the same classpath. The [app wrapper](https://raw.githubusercontent.com/leaningtech/javafiddle/main/src/app.html) uses **https://cjrtnc.leaningtech.com/4.3/loader.js**. The additional [tools.jar asset](https://github.com/leaningtech/javafiddle/blob/main/static/tools.jar) is displayed by GitHub as **17.5 MB**; this is repository metadata, not measured transfer size. Its exact JDK build/provenance/license contents/hash remain unreviewed. Do not assume the demo repository's Apache license covers OpenJDK binaries.

The [run API](https://cheerpj.com/docs/reference/cheerpjRunMain) accepts class, virtual classpath and arguments and returns an exit-code Promise. The [init API](https://cheerpj.com/docs/reference/cheerpjInit) supports Java 8/11/17 selection, with 8 the default. The demo uses `cheerpjAddStringFile`; current reference navigation names `cheerpOSAddStringFile`. Verify exported APIs against the actual 4.3 loader instead of mixing historical examples.

**Licensing fact:** [Current licensing documentation](https://cheerpj.com/docs/licensing) permits community CDN use for eligible personal/FOSS projects and technical evaluations, requires appropriate credit, and gates self-hosting behind a commercial license. Academic institutional use is directed to a tailored quote. A two-student prototype must not be casually equated with permission for institutional production or self-hosting. No deployment/license eligibility determination was made here.

**Network/security fact:** [Networking documentation](https://cheerpj.com/docs/guides/Networking) explicitly supports same-origin HTTP(S) through fetch and general networking through Tailscale. [FAQ](https://cheerpj.com/docs/faq) describes on-demand runtime loading and Java-to-browser API access. A same-origin app deployment therefore fails the intended isolation assumption unless additional boundaries are proven. CDN runtime allowances also complicate disabling all program-time network. Never configure Tailscale credentials for the untrusted runner. No current 4.3 worker/termination/stdin API was proven; search results for CheerpJWorker led to deprecated CheerpJ 2 docs and are not evidence for 4.3.
