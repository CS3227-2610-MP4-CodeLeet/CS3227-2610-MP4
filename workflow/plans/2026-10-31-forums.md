# Forums implementation plan

Issue [#30](https://github.com/CS3227-2610-MP4-CodeLeet/CS3227-2610-MP4/issues/30), branch `feat/forums` from develop `d9511ba`. Active change: `build-programming-platform`, task group 14.

## Design

Deliver the user's requested independent feature: one shared text forum for the existing course and both provisioned roles. Use persistent threads/replies instead of a live-chat service or assignment-coupled discussions. Author usernames and roles are server-derived snapshots at posting time; no new public profile query. Existing submissions, rubrics and grades remain private.

Pages `/forums`, `/forums/new`, `/forums/[threadId]` require verified identity and a trusted student/instructor role. Reuse the student workspace and instructor header. Add Forums to authenticated student sidebar/mobile Menu and instructor navigation. Plain-text title/body, role and Singapore timestamp; React escapes content. Threads/replies are newest-first with stable timestamp/ID sorting, 25 rows and one lookahead. Provide loading/empty/unavailable/error states. Retain inputs on failure, disable pending inputs and show the newest reply on success.

Atomic RPC derives identity/profile/role/time, validates non-whitespace titles (1–160 characters), bodies (1–8,000 characters) and UUID request IDs, and serializes per-user writes. Implementation lives in an unexposed schema with an authenticated public invoker wrapper. RLS-protected projected reads; no direct client insert/update/delete. Ten combined posts per user per rolling minute; identical retries succeed before quota, mismatched retries conflict. Bound API JSON to 34,000 bytes and require same Origin. No client author, role, timestamp or grade fields.

Initial slice supports creation/reading. No editing/deletion, live chat, uploads, Markdown/HTML, reactions, private messaging, AI or XP. No general moderation system is claimed. Preserve unrelated `next-env.d.ts`. Implement directly; no delegated specialist runs or independent review are claimed.
