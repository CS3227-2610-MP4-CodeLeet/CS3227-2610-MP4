## Agreed product rule and design

The requester chose accepting late submissions and marking them Late, with no automatic grade penalty. Use optional deadlines and SGT input/display; store finite timestamptz instants. Existing assignments retain no deadline. Each new revision captures the assignment deadline and whether its database creation time is strictly later; exactly equal is on time. Deadline edits/removal affect later revisions only. Identical request retries return original metadata. The requester authorized shared schema/API work; teammate review is pending, not claimed.

Approaches: rejecting late saves conflicts with the chosen policy; computing historic lateness solely from the current deadline would silently rewrite history. Choose database-owned captured metadata with a forward migration and existing row locks/RPCs. Assignment list/workspace states use the latest own revision: Not submitted, Overdue (past due with no saved revision), Submitted or Submitted late. Status is evaluated on loading/refresh/save, with no polling/countdown. Revision/detail/history and authorized instructor review show captured timing. No grade, XP, AI or execution changes.
